# Compute Lineage Atlas — before the 1837 formal root

**Status:** evidence-backed research seed, not canon  
**Checked:** 2026-09-22  
**Purpose:** preserve the deeper history of embodied computation so future AXM compute work does not mistake modern silicon architecture for the definition of computation.

## Why this file exists

The runtime Compute Substrate Lab currently protects a narrow working root at 1837:

- scope: formal programmable general-purpose machine lineage;
- subject: Babbage's Analytical Engine;
- status: provisional working root, not a claim that earlier computation did not exist.

That root is useful for one particular lineage. It is not a valid boundary for the broader history of physical computation.

The broader record reaches much further back.

This atlas therefore keeps several lineages separate instead of forcing every historical object into the modern word "computer."

## Scope ladder

A historical device can contribute to compute history without satisfying every later property.

| Scope | Meaning |
|---|---|
| external symbolic state | physical marks/positions preserve number or state outside the human mind |
| manual calculating aid | a human performs the sequence while a physical structure reduces effort/error |
| physical analog calculator | physical geometry or motion directly represents mathematical relations |
| mechanical arithmetic automation | the mechanism performs arithmetic state transitions |
| encoded machine control | an external pattern instructs a machine how to behave |
| automatic calculation engine | a machine executes a fixed class of calculations with reduced human intervention |
| programmable general-purpose architecture | program/control representation can direct a machine across a broad class of calculations |

Do not silently promote an object from one scope into another.

For example:

- an abacus is not the same thing as a programmable computer;
- a punched-card loom is not a general-purpose calculator;
- the Antikythera Mechanism is not a stored-program digital computer;
- all three still contain important compute-substrate lessons.

## Grounded pre-1837 lineage

### ca. 4th century BCE — Salamis counting board / table abacus

The Computer History Museum identifies the Salamis tablet as apparently the oldest surviving calculating device. It is a physical counting surface rather than an autonomous machine.

**What it contributes:**

- externally represented numerical state;
- positional manipulation;
- reusable physical state without electronics;
- a reminder that "memory" can begin as arrangement, not stored voltage.

**Source:**

- Computer History Museum — Salamis tablet: https://www.computerhistory.org/revolution/artifact/1/128
- Computer History Museum — abacus overview: https://www.computerhistory.org/revolution/story/1

**Boundary:** this does not establish the beginning of human computation. It is a surviving calculating-device milestone.

---

### late 2nd century BCE — Antikythera Mechanism

Modern research dates the Antikythera Mechanism to around the end of the second century BCE. It used complex bronze gearing to calculate/display astronomical cycles and predict events such as eclipses.

Nature Astronomy describes it as the oldest known mechanical calculator. Nature's 2006 reconstruction work supports its role as an ancient astronomical calculator, and later work describes it as a mechanical computer for astronomical prediction.

**What it contributes:**

- physical state encoded in gear position;
- mechanical composition of multiple mathematical cycles;
- analog/mechanical representation of a model;
- computation embedded directly into geometry and ratios;
- specialized hardware whose "program" is largely embodied in structure.

**Sources:**

- Nature, 2006: https://www.nature.com/articles/nature05357
- Nature Astronomy, 2018: https://www.nature.com/articles/s41550-017-0347-2
- Scientific Reports, 2021: https://www.nature.com/articles/s41598-021-84310-w

**Boundary:** it is specialized astronomical computation, not evidence of a general-purpose programmable architecture.

---

### 1617 — Napier's Bones

John Napier published a compact calculating aid that reduced multiplication/division to simpler operations using inscribed rods. The Computer History Museum notes that the underlying table-based method has older roots outside Europe.

**What it contributes:**

- precomputed structure used as a compute accelerator;
- complexity reduction by changing representation;
- a physical "lookup structure" rather than brute-force arithmetic;
- evidence that useful compute architecture can be partly algorithm and partly artifact.

**Sources:**

- Computer History Museum: https://www.computerhistory.org/revolution/calculators/1/45
- Computer History Museum: https://www.computerhistory.org/tdih/april/3/

---

### 1620s — logarithmic scales and slide rules

Gunter's logarithmic scale (1620) and Oughtred's slide-rule work in the 1620s embodied logarithmic relationships in physical distance.

**What it contributes:**

- analog computation by geometric relation;
- transformed representation turning multiplication into addition of distances;
- a direct example of algorithm + physical encoding co-design.

**Sources:**

- Computer History Museum — slide rules: https://www.computerhistory.org/revolution/story/44
- Computer History Museum — Oughtred: https://www.computerhistory.org/revolution/calculators/1/44/154

---

### 1623 — Wilhelm Schickard's calculating clock

Schickard described mechanical calculators in letters/sketches to Johannes Kepler. The Computer History Museum describes the design as the earliest known mechanical four-function calculator, combining Napier-style multiplication/division aids with toothed-wheel addition/subtraction.

**What it contributes:**

- arithmetic state transitions embodied in gears;
- carry propagation as a physical mechanism;
- composition of separate calculation techniques into one machine.

**Sources:**

- Computer History Museum: https://www.computerhistory.org/revolution/calculators/1/47
- Computer History Museum artifact: https://www.computerhistory.org/revolution/calculators/1/47/194

**Boundary:** the original machines do not survive; knowledge comes from historical documentation.

---

### 1640s — Pascaline

Blaise Pascal developed geared adding machines in the 1640s. The Computer History Museum notes that roughly fifty were built, making it an early calculating machine produced in more than one-off quantity.

**What it contributes:**

- automatic decimal carry;
- repeated physical manufacturing of a computational mechanism;
- user input separated from the internal carry mechanism.

**Sources:**

- Computer History Museum: https://www.computerhistory.org/revolution/calculators/1/47
- Computer History Museum design record: https://www.computerhistory.org/revolution/calculators/1/47/196

---

### 1673 onward — Leibniz Stepped Reckoner

Leibniz's stepped-drum design enabled four-function mechanical calculation and became an extremely durable mechanism family in later calculators.

**What it contributes:**

- reusable computational primitive;
- one physical mechanism reused across many generations of machines;
- a strong historical example of a substrate-level primitive surviving product generations.

**Sources:**

- Computer History Museum: https://www.computerhistory.org/revolution/artifact/49/198
- Computer History Museum: https://www.computerhistory.org/revolution/story/49

---

### 1725 — Basile Bouchon: perforated-paper machine control

Bouchon used perforated paper to control parts of a draw loom. This is important because the information pattern is physically separated from the machine mechanism.

**What it contributes:**

- external machine-readable control state;
- replaceable instructions without rebuilding the whole machine;
- early separation between mechanism and encoded operation.

**Sources:**

- Computer History Museum historical overview: https://computerhistory.org/blog/relax-machines-already-took-our-jobs/
- Computer History Museum catalog material: https://tcm.computerhistory.org/DCM/DigitalComputerMuseumCatalog1981Thelen.pdf

---

### 1728 — Jean-Baptiste Falcon: punched-card control

Falcon replaced Bouchon's perforated paper roll with linked punched cards. The Science Museum Group describes Falcon's loom as the first machine of any kind controlled by punch cards, following Bouchon's 1725 perforated-paper control.

**What it contributes:**

- modular instruction units;
- reorderable/extendable encoded control;
- durable control media distinct from the controlled machine.

**Sources:**

- Science Museum Group: https://collection.sciencemuseumgroup.org.uk/objects/co44927/model-of-falcons-loom
- Computer History Museum catalog material: https://tcm.computerhistory.org/DCM/DigitalComputerMuseumCatalog1981Thelen.pdf

---

### mid-1740s — Jacques de Vaucanson: more automatic loom control

Vaucanson further automated the punched-pattern loom lineage. Institutional histories place this development in the mid-1740s; exact year differs between historical summaries.

**What it contributes:**

- increased automatic sequencing;
- tighter integration between stored control pattern and machine motion;
- evidence that automation and programmability evolved incrementally rather than appearing in one invention.

**Sources:**

- Computer History Museum: https://computerhistory.org/blog/artifact-adopted-preserving-the-legend-of-j-m-jacquard/
- Computer History Museum catalog material: https://tcm.computerhistory.org/DCM/DigitalComputerMuseumCatalog1981Thelen.pdf

---

### 1801 / 1804–1805 — Jacquard control mechanism

Joseph-Marie Jacquard demonstrated punched-card-controlled weaving in 1801 and developed the commercially successful control system in the following years.

The cards encoded repeatable machine operations. This lineage directly influenced Babbage's later use of punched cards for the Analytical Engine.

**What it contributes:**

- reusable stored control;
- machine behavior driven by external symbolic patterns;
- repeatable "program" separate from the mechanism;
- practical industrial deployment of encoded machine control.

**Sources:**

- Computer History Museum: https://www.computerhistory.org/storageengine/punched-cards-control-jacquard-loom/
- Computer History Museum: https://www.computerhistory.org/revolution/story/4
- Science Museum Group: https://collection.sciencemuseumgroup.org.uk/objects/co44888/model-of-a-jacquard-loom-model-jacquard-loom

**Boundary:** the loom is programmable control for weaving, not a general-purpose arithmetic computer.

---

### 1820 — Thomas de Colmar's Arithmometer

The Arithmometer brought four-function mechanical calculation into the industrial-manufacturing era and became commercially successful.

**What it contributes:**

- computational mechanism + manufacturability;
- reliability and production engineering becoming part of compute viability;
- the lesson that an architecture matters only if it can be made repeatedly.

**Sources:**

- Computer History Museum: https://www.computerhistory.org/revolution/calculators/1/52
- Science Museum Group: https://collection.sciencemuseumgroup.org.uk/objects/co59719/thomas-de-colmars-arithmometer-with-mahogany-case-lid

---

### 1821–1832 — Babbage Difference Engine lineage

Babbage began work on Difference Engine No. 1 in 1821. It was designed to calculate and tabulate polynomial functions and mechanically couple calculation to printing.

**What it contributes:**

- automatic multi-step calculation;
- output generation integrated with compute;
- decomposition of a large calculation into deterministic mechanical stages;
- an important bridge from calculator to automatic calculating engine.

**Source:**

- Computer History Museum: https://www.computerhistory.org/babbage/engines

**Boundary:** Difference Engine is specialized, not general-purpose programmable computation.

---

### 1834 conception / 1837 formal boundary — Analytical Engine

Babbage conceived the more ambitious Analytical Engine in 1834. The Computer History Museum describes it as a general-purpose programmable computing engine with punched-card programming, a "Store" for numbers/intermediate results and a separate "Mill" for arithmetic processing.

The active AXM Compute Substrate Lab currently protects **1837** as its provisional formal root for the narrower scope:

FORMAL_PROGRAMMABLE_GENERAL_PURPOSE_MACHINE_LINEAGE

This atlas does not silently replace that root. It explains what came before it and why the broader compute story is much older.

**Sources:**

- Computer History Museum: https://www.computerhistory.org/babbage/engines
- Computer History Museum overview: https://www.computerhistory.org/babbage/overview/

## What changed across the lineage

The useful history is not just a list of old objects. Several reusable architectural ideas appear gradually.

### State escaped the mind

Counting boards and physical markers externalized state.

### Mathematics became geometry and mechanism

Slide rules and the Antikythera Mechanism show that physical relationships can directly perform useful transformations.

### Arithmetic became automatic state transition

Mechanical calculators moved carries, digits and arithmetic relationships into gears and mechanisms.

### Instructions separated from the machine

Bouchon, Falcon, Vaucanson and Jacquard moved control into an external physical representation.

### Program-like control became reusable

Punched media made machine behavior repeatable without reconstructing the entire mechanism.

### Computation became architecture

Babbage's Analytical Engine separated storage and processing and targeted a general-purpose programmable machine.

## Lessons for future AXM compute substrates

### 1. Do not start from "chip"

Start from:

- state carrier;
- allowed transformations;
- memory/retention;
- control representation;
- communication;
- error behavior;
- energy;
- fabrication;
- recovery.

A transistor is one answer to those questions.

### 2. Structure itself can compute

Gearing, spatial arrangement and material behavior can encode transformations. Not every useful computation must imitate Boolean CMOS internally.

### 3. Representation changes cost

Napier's Bones and slide rules show that choosing a representation can remove expensive operations.

Future substrate research should ask:

> Can the physical representation make the target operation cheap or native?

### 4. Program and substrate can be separated by degrees

There is a continuum:

~~~text
behavior fixed in geometry
-> adjustable parameters
-> external encoded control
-> reusable program
-> general-purpose programmable architecture
~~~

Do not force every candidate into only "hardwired" or "software."

### 5. Manufacturability is part of computation

The Arithmometer lineage shows that a brilliant mechanism which cannot be built reliably and repeatedly is not equivalent to a deployable compute substrate.

### 6. "Old" does not mean exhausted

Mechanical, analog and encoded-control ideas can become newly useful when paired with:

- modern materials;
- cheap sensors;
- precision fabrication;
- simulation;
- automated design search;
- machine-generated control logic;
- modern electronics only where needed.

The research question is not "should we go back?"

It is:

> Which computational principles were abandoned because of the constraints of their time, and do those constraints still hold?

## Future extraction target

This historical atlas is intended to feed a later dedicated repository for personal compute structures / custom substrate design.

That future work should extract **primitives**, not copy historical machines.

Candidate primitive families:

- positional state;
- geared ratio/state transformation;
- analog geometric transform;
- lookup/precomputed transform;
- carry/propagation mechanisms;
- external control media;
- sequenced control;
- modular instruction representation;
- separated state and transformation;
- reversible/mechanically recoverable state;
- hybrid physical + electronic control.

## Truth boundary

This file deliberately avoids a universal "first computer" claim.

"First" changes with the definition:

- first surviving calculating device;
- first known mechanical calculator;
- first punched-card-controlled machine;
- first automatic calculating engine;
- first general-purpose programmable design;
- first electronic implementation;
- first stored-program implementation.

Those are different questions.

The goal of AXM Compute Substrate is not to win a historical naming argument. It is to preserve the architecture ideas, evidence and constraints that can help us design future computation.
